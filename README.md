# 学校打印耗材退件判别

澄江学区后勤耗材质检组。澄江一小、澄江实验中学和澄江职校的打印耗材由 4 人后勤质检组集中处理。校点送检员核对耗材实物编号并登记检测值，质检组将标准页复测和实物检查结论录入台账，采购组凭复核清单办理供应商退换。

导入 cartridge-returns-2026-11-23.csv，包含耗材编号、校点、检测日期、固定分组、质检结论和标准页检测值。训练、留出组使用实物检查已确认的退件或留用结论，候选组填写待判。三个检测值均填 0 至 100 的百分数。 在同一留出组比较成本阈值与固定 0.5 阈值的错判成本、混淆计数及召回率，并按退件后验为候选件排序。质检员查看每项检测值和带符号的对数赔率贡献，复核后将 CSV 发给采购质保组。

- 校点用不同工作表跟踪补打、换盒和送检，复测时容易重复登记同一耗材。
- 质检员过去凭单项条纹或剩余耗材率判断，漏退后还要安排重新上门并补印材料。
- 采购组收到的清单只有退件结论，难以核对检测依据，也缺少同批错判成本对照。

## 六个业务模块

1. 学区退件总览
2. 耗材送检台账
3. 退件成本试算
4. 留出与候选明细
5. 质保退件复核
6. 采购清单分发

## 工作剧本

1. 08:20，后勤组清点 3 个校点送来的 12 件待判耗材，首箱实物编号为 CJ-2611-121。
2. 08:50，导入 cartridge-returns-2026-11-23.csv 共 132 行，锁定 11 月 2 日至 6 日的 80 件训练记录，以及 11 月 16 日至 20 日单独登记的 40 件留出记录。
3. 09:10，按采购组的复核估价设置误退 35 元、漏退 115 元，运行得到约 23.33% 的成本退件阈值。
4. 09:20，打开 40 件留出明细，成本规则发生 5 件误退、4 件漏退，错判计 635 元，同批 0.5 阈值为 865 元。
5. 09:35，逐件复核 5 件建议退件。CJ-2611-121 的条纹覆盖率为 24%，是该件最强的退件证据。
6. 10:00，复核员确认建议，导出含 12 条候选及 40 条留出的 52 行报告，并设置 16:30 向采购质保组站内分发。

## 算法与复核

高斯朴素贝叶斯用固定训练组估计经验类先验、类内均值和总体方差，方差下限为 0.01 平方百分点。将先验对数赔率与各特征对数似然比相加得到退件后验。以误退成本除以两种错判成本之和作为退件阈值。各特征采用条件独立假设，后验为模型估计。每次运行按相同分组复现，演示台账种子为 702411。

同一实物编号重复、分组或质检结论无效、日期或检测值格式错误，以及成本超出范围时会指出修正方式。训练组每类至少 2 件，留出组每类至少 1 件，另需至少 1 件待判候选。 复核问题为「是否接受本批建议退件清单，哪些候选件需要先复测标准页？」。每次分析绑定数据版本和参数，原始数据按规范化内容的 SHA-256 去重。日程针对已复核的固定结果版本，每日模式按初次投递时间每 24 小时重复。停机期间错过多次时只补一份到站内收件箱，下一次回到原时间点。

| 字段 | 含义 | 类型 |
|---|---|---|
| `cartridge_id` | 耗材编号 | str |
| `school` | 校点 | str |
| `inspected_on` | 检测日期（YYYY-MM-DD） | str |
| `cohort` | 固定分组（训练、留出、候选） | str |
| `verified_label` | 质检结论（退件、留用、待判） | str |
| `remaining_pct` | 剩余耗材率（%） | float |
| `streak_pct` | 条纹覆盖率（%） | float |
| `density_error_pct` | 密度偏差率（%） | float |

## 启动

```sh
[ -f .env ] || cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

- Web 界面 `http://127.0.0.1:18294`
- API 文档 `http://127.0.0.1:19294/docs`
- 数据库端口 `17794`

| 账号 | 演示密码 | 工作权限 |
|---|---|---|
| analyst | analyst-demo-24 | 导入 CSV、运行分析、导出工作稿 |
| reviewer | reviewer-demo-24 | 复核、设置和停止投递、导出 |
| viewer | viewer-demo-24 | 浏览结果、导出已批准的报告、查收投递 |

原生 HTML/CSS/JavaScript 前端与 Nginx、FastAPI、Python worker、PostgreSQL 16 和 Redis 组成五服务 Compose。`backend/src/services/domain.py` 存放业务算法，`domain.json` 定义字段与验收口径，`frontend/src/pages` 为业务页面。更新任一侧源文件后，用 `docker compose up -d --build` 重建对应镜像。`backend/src/constants/enums.py` 和 `frontend/src/constants/enums.js` 定义角色及运行状态。`.env` 支持前端、API、数据库端口、演示 seed 开关和 JWT 密钥。首次部署到非演示环境时更换演示身份及 JWT/数据库凭据。

`docker compose down` 停止服务并保留数据卷。现场数据和演示结果可以在各自版本中并存。
